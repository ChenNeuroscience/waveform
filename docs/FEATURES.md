# Original feature inventory and migration

Audited source: `gh-pages` at `bf0f51bd75cd44a6edecfa09e10e5ae68c5961c8`, especially `index_full.html`, `file-organiser.html`, `parsed-data.html`, `cut-object.html`, `wave-plots.html`, `cluster-plots.html`, `rm-plots.html`, `tac-plots.html`, `tile-wall.html`, `tile-element.html`, `header-view.html` and `undo-stack-view.html`. This inventory concerns the working original, not the abandoned rewrites.

The original source is preserved on the [waveform-v1 branch](https://github.com/ChenNeuroscience/waveform/tree/waveform-v1); generated legacy bundles have been removed. The initial screen restores the drag/drop prompt, supported extensions, source link and original video. After import, files/position/features occupy the left panes (350 px default, 240 px minimum) and compact cell tiles fill the right.

## Scope and scientific interpretation

This is a browser exploration and manual-cut editor, not an automatic spike sorter. It does not introduce PCA, automated clustering, gridness scores or place-cell classifications absent from the audited application. It does not load continuous EEG/EGF signals.

The modern workflow covers the core import/explore/edit/export tasks. Remaining differences include bounded waveform/projection rendering, sampled large autocorrelograms and a simpler LED-swap heuristic. The compact light layout, resizable left panes, tile wall, drag editing, hover and Space-copy interactions follow the original. The original and replacement analysis results have not been shown numerically equivalent on curated labelled biological reference data. Validate analysis settings and results against the laboratory's established pipeline before relying on them for quantitative research conclusions.

Sampled plots display **WARNING: using sampled rendering** on hover; full-population rendering is deferred. The organiser keeps cuts inline with tetrodes at both collapsed and expanded sizes, remembers the last selected cut per trial/tetrode, and distinguishes modified cuts by colour. Prepared cut files can be dragged out using native Chromium drag data; a cold export must be prepared before dragging. The position pane has no title bar: recorded start/end clock times, total minutes and speed occupancy stay visible over a faint white backing. The cell badge overlaps the tile corner, with a fixed gap above speed tuning and aligned side-by-side badges during drag-snap.

The footer has been removed; spike count, duration, cache size and progress appear compactly at the right of the main toolbar. The feature grid is centred within its pane. Rendering controls remain in Settings, while its isolate/drift/density checkboxes and numeric split form are absent. Right-drag split mode remains available on tiles. Space copies drag from anywhere in their content and cannot be resized manually.

Trial, tetrode and cut choices participate in browser Back/Forward navigation. Other controls and cut edits do not add navigation entries. The click-only simulated-files card creates five trials with eight tetrodes each, approximately 50k spikes over 20 minutes, noisier waveforms and exploration biased towards less-visited squares of a 1 m box.

Feature editing defaults to paint; there is no separate select tool. Region cutting uses a lasso icon. Group chips wrap, and square projections have complete borders and 4 px gaps, including borders in Space copies.

The painting group selector uses the original set notation and mouse/keyboard rules. Tile clicks focus feature points independently of the source set, using GPU depth ordering without re-uploading population buffers. The bottom-left merge/swap buttons and numeric destination field are removed. While hovering a tile, press `S` to swap that group. A centred prompt focuses the target input; type a number and press Enter, click a second tile, or use an offered −1/+1 move into an empty adjacent number. The source keeps the original hover glow. Entering swap mode makes no cut changes. Escape or recording navigation cancels; completed swaps preserve per-cut undo/redo. Successful merges and swaps jiggle their updated result tiles using the existing settling animation.

Painting uses a brush icon. Remaining groups start on a new row below the tools and set notation, and the new-destination + button follows the remaining groups.

Short source sets use compact braces; wrapped sources align within braces spanning all rows, with the tools kept on the first line. Edit history contains undo/redo and plain action rows, without export/duplicate buttons, completion checkmarks or storage-location wording.
